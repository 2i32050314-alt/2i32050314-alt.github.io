🔤 命名风格转换

camelCase / snake_case / kebab-case 一次转好










命名转换看着简单，坑在边界


userID、user_id、APIKey、HTMLParser 这些词，如果只按大写字母切分，会得到 user_i_d、a_p_i_key 这种灾难。这个工具先做两步拆分：小写/数字后面跟大写处断开，连续大写后面跟「大写+小写」处再断开，所以 HTMLParser 会被切成 HTML + Parser，userID 切成 user + ID。


每种风格的约定


    

  • camelCase：变量、函数（JS/Java 惯例）。
    • 

  • PascalCase：类、组件、类型。
    • 

  • snake_case：Python 变量、SQL 字段、环境变量（配合全大写）。
    • 

  • kebab-case：CSS 类名、URL 路径、文件名（因为某些系统不区分大小写，连字符比下划线更安全）。
    • 



实际用途


从数据库字段名直接生成前端变量名，或者反过来把一批 CSS 类名统一掉。批量处理时建议先复制到表格里逐条确认——缩写词（如 ID、URL、HTTP）的期望写法因人而异，工具给的是最常见的处理方式，不一定等于你团队的规范。


为什么 userID 会变成 userId 而不是 userID？
camelCase 的惯例是把后续单词首字母大写、其余小写。要保留全大写缩写，需要手工调整。
中文能转吗？
不能。中文没有大小写概念，工具会把中文当成一个词原样保留，通常没有意义。
能一次转一批吗？
每行一个词贴进来，工具会按整段处理；批量建议在编辑器里用多光标或脚本。
