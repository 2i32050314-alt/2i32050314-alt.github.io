粘贴的 JSON 老是报错？九成是这三个原因

2026-11-08　·　Demo_Li

JSON 的语法规则只有一个页面那么长，但报错信息通常只有一句 Unexpected token，位置还常常指向一个看起来完全正常的地方。原因在于解析器读到非法字符的那一刻才报错，而问题往往出现在它前面。

下面三类占了绝大多数情况。

一、最后一个元素后面多了逗号

{
  "a": 1,
  "b": 2,
}

JavaScript 里这是合法的（尾随逗号从 ES5 起就允许），JSON 里不是。解析器读到收尾的 } 之前那个 ,，期望的是一个键名，于是报 Unexpected token }。看到报错指向右花括号或右方括号，先往左看一个字符。

二、用了单引号

JSON 规范要求字符串和键名都必须用双引号。从 Python 字典打印、从某些日志、从手写的配置片段复制过来的内容，经常带着单引号：

{'name': 'test'}

报错通常出现在第一个单引号处，信息类似 Unexpected token '。全量替换成双引号即可，但字符串内部如果本来就有双引号，需要转义。

三、不可见的字符

这一类最难查，因为复制出来的内容看起来是对的。常见的有：

  • 从网页复制时带上的全角逗号，或中文引号；
  • 从 Excel 复制时带上的制表符；
  • 文件开头或结尾的 BOM，在编辑器里完全看不见。

判断方法很直接：把内容粘贴到能显示不可见字符的编辑器里，或者用本工具解析。报错的列位置通常正好落在那个字符上。

另外两种会被误认成语法错误的情况

数字格式不对。JSON 不允许 +1、.5、01 这种写法，也不允许 NaN 和 Infinity。要表示它们只能改成字符串。

注释。JSON 标准里没有注释。很多工具接受带注释的变体，但 JSON.parse 不接受。把注释删掉再解析，或者在构建步骤里换成支持 JSON5 的解析器。

报错位置怎么用

本工具会把报错里的字符偏移换算成第几行第几列。拿到位置后不要只盯那一列，往回退一到两个 token 看。尤其是遇到以 }、] 结尾的报错时，问题几乎总在它前面那个逗号。

顺带说一句，工具会显示节点数量和输出体积。有时候你以为是格式问题，实际是把两份不同的数据贴串了，体积差一倍就能看出来。
