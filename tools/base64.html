🔐 Base64 / URL 编解码

中文不会乱码的 Base64，一并处理 URL 参数










Base64 不是加密


这是最常被误解的一点：Base64 只是把二进制转成 64 个可打印字符，任何人拿到都能还原。它解决的是「二进制数据没法安全放进纯文本协议」的问题，比如把图片塞进 CSS、把二进制签名放进 HTTP 头、把中文放进只接受 ASCII 的字段。


中文为什么会乱码


btoa() 只接受 Latin-1 字符，直接传中文会抛 InvalidCharacterError。正确做法是先 TextEncoder 编成 UTF-8 字节，再转 Base64。这个工具内置了这一步，所以中文、emoji 都不会出问题；解码时同理，先把字节还原再按 UTF-8 解释。


URL 编码的区别


URL 编码（百分号编码）只转义在 URL 里有特殊含义的字符（空格、&、=、中文等），结果里保留大量可读字符。同一个字符串，Base64 结果通常更长，URL 编码结果更短且可读。


典型用途


    

  • 把一段 JSON 放进 URL 参数（Base64 URL-safe 变体需要把 + / 换成 - _）。
    • 

  • 检查邮件头、JWT 的 payload 段（JWT 用的是 Base64URL，去掉尾部 =）。
    • 

  • 快速看一段乱码是不是 Base64：如果全是 A-Za-z0-9+/= 且长度是 4 的倍数，基本就是。
    • 



Base64 会让体积变大多少？
约 33%。因为 3 个字节变成 4 个字符。
为什么解码时报「不是合法的 Base64」？
常见原因：尾部 `=` 被截断、混入了换行以外的空白、用了 URL-safe 的 `-` `_` 而工具按标准表解析。
能用来加密吗？
不能。Base64 无密钥，等于明文传输。要加密请用 AES 等真正的加密算法。
