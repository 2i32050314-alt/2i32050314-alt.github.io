🧾 哈希校验（SHA）

算文本或文件的 SHA 值，核对下载是否完整










哈希用来干什么


校验文件完整性：下载完对一下官方公布的 SHA-256，一致说明没被篡改、没传坏。或者比对两份配置是否「逻辑上完全相同」——哈希不同则内容必有差异。


算法怎么选


    

  • SHA-256：默认选它，够安全也够快。
    • 

  • SHA-1：已被证明可构造碰撞，只用于兼容老系统，不要用于安全场景。
    • 

  • SHA-384 / SHA-512：更长的输出，安全裕度更高，速度略慢。
    • 

  • MD5：只用于判断「文件是否相同」这类非对抗场景，绝不能用于校验下载包的完整性。
    • 



一个常见误解


哈希不是加密，不可逆。但简单文本（比如常见密码）的哈希可以被彩虹表反查，所以密码存储要用加盐 + 慢哈希（bcrypt、scrypt、Argon2），而不是直接 SHA-256。


实现细节


使用浏览器原生 WebCrypto。注意它只在 HTTPS 或 localhost 下可用——用 file:// 直接打开本地 HTML 会拿不到 crypto.subtle。


文件的哈希要下载完整文件才能算吗？
是的。哈希是逐字节计算的，必须读完全部内容。大文件会占用一些内存和几秒时间。
为什么同样的文本，我算出来和别人不一样？
多半是编码或换行差异：Windows 的 CRLF 与 Unix 的 LF，或者末尾多了一个换行。
支持 MD5 吗？
WebCrypto 不提供 MD5。需要用 MD5 的场景（老接口签名）请用专门的库。
