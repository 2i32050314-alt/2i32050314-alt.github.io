🧩 JSON 格式化 / 校验

粘贴一段 JSON，立刻看出哪里多了一个逗号










什么时候需要它


接口返回了一大段挤在一起的 JSON，肉眼找不到那个多余的逗号；或者线上和本地两份配置结构不一致，想按字母序排一下再比对。这个工具做的事很单一：解析、报告错误位置、按你选的方式输出。


使用要点


    

  • 格式化：2 空格缩进，方便逐行看层级。
    • 

  • 压缩：去掉所有空白，用于塞进 URL 参数或配置文件。
    • 

  • 键名排序：递归按字母序重排所有对象的键，用于对比两份本该相同的 JSON。注意数组顺序不会被改动，所以数组里的元素顺序依然是有意义的差异。
    • 

  • 报错会指出第几行第几列。JSON 的常见错误只有三类：多余的逗号（最后一个元素后面）、用了单引号、键名没加引号。
    • 



一个容易踩的坑


JSON.parse 对制表符、全角引号、中文逗号一律不容忍。从 Excel 或聊天软件里复制出来的内容，先确认引号是半角 "。如果你的内容里确实有中文引号，属于字符串内容而非语法符号，那没问题——只要它在引号内部。


隐私说明


解析在浏览器里完成，粘贴的内容不会发到任何服务器。涉及密钥、客户数据的内容可以放心处理（但仍建议不要整段贴进任何联网页面）。


JSON 和 JavaScript 对象字面量有什么区别？
JSON 更严格：键必须用双引号、不能有注释、不能有尾逗号、不能有 undefined 和函数。JS 对象字面量这些都允许，所以能跑的 JS 代码不一定能当 JSON 解析。
为什么我的 JSON 只有一行，格式化后变长了很多？
缩进和换行都是合法空白，只是给人看的。体积敏感的场景（URL 参数、嵌入配置）用「压缩」输出即可。
大文件会卡吗？
几 MB 的文本在普通电脑上是毫秒级。超过 50 MB 浏览器可能明显卡顿，建议改用命令行 jq。
