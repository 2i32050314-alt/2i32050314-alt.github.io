🔍 正则表达式测试

边写边看匹配位置和分组，不必来回改代码

匹配高亮









正则调试最烦的两件事


一是贪婪 vs 懒惰：.* 会一路吃到行尾，.*? 才会在第一个匹配处停下。二是全局匹配下的 lastIndex：带 g 标志的正则在 exec 时是有状态的，循环里忘了处理空匹配会死循环。这个工具在循环时会自动跳过空匹配，避免页面卡死。


分组怎么看


    

  • ( ) 是捕获组，结果里按 $1、$2 顺序给出。
    • 

  • (?: ) 是非捕获组，只分组不占编号。
    • 

  • (?<name> ) 是命名组，结果里直接显示名字，比数括号可靠得多。
    • 



常用速查


    

  • \d 数字，\w 字母数字下划线，\s 空白。
    • 

  • ^ $ 行首行尾（配合 m 标志才是每行开头结尾）。
    • 

  • [^abc] 排除；a{2,4} 重复 2 到 4 次。
    • 

  • 中文范围 [\u4e00-\u9fa5]；全角标点 [\u3000-\u303f]。
    • 



一个提醒


不要用正则解析 HTML 或 JSON——嵌套结构超出正则的表达能力，容易出现「测着好好的，换个页面就崩」。这类场景请用真正的解析器。


为什么同一个正则，有的语言能跑有的报错？
各语言实现（PCRE、RE2、JS）对后行断言、命名组语法、Unicode 属性支持不同。JS 不支持变长后行断言。
g 标志加了之后结果变少了？
global 匹配会从上次结束位置继续，如果手动多次调用 exec 又不重置 lastIndex，就会跳过前面。
怎么匹配换行？
JS 里用 `[\s\S]` 或加 `s` 标志让 `.` 匹配换行。
